# 과제 #7 요구사항 명세

## 목적

Team 5가 과제 #5에서 만든 공유 업무 DB를 Python 백엔드와 CLI로 사용할 수 있게 한다. 기존 정규화된 `issues`, `statuses`, `users`, `labels` 데이터를 그대로 사용한다.

## 사용자

- **팀원**: CLI로 업무를 조회하고 생성·수정·이동·삭제한다.
- **Codex**: 저장소 작업의 진행 상황을 팀 보드에 기록한다.

## 기능 요구사항

1. 상태 열을 조회한다: Backlog, Ready, In Progress, Done.
2. 전체 업무 또는 상태별 업무를 조회한다.
3. 업무를 생성하고 제목, 설명, 상태, 담당자, 마감일, 우선순위, 라벨을 저장한다.
4. 업무의 제목, 설명, 상태, 담당자, 마감일, 우선순위, 라벨을 수정한다.
5. 상태 변경을 `status_history`에 기록하고 Done으로 이동한 업무는 `closed_at`을 설정한다.
6. 업무를 삭제하면 연결된 댓글, 담당자, 라벨, 상태 변경 기록도 기존 외래키의 cascade 규칙에 따라 삭제한다.
7. API 문서와 CLI 도움말을 제공한다.
8. Codex가 작업을 보드에 등록하고 상태를 갱신하는 저장소 스킬을 제공한다.

## 비기능 요구사항

- Python 3.11과 `uv`를 사용한다.
- 로컬에서 실행하며 기본 바인딩은 `127.0.0.1`이다.
- Supabase 서버 키는 API에서만 읽고 CLI와 저장소에 넣지 않는다.
- 로그인 기능은 구현하지 않는다. 공개 주소에 API 서버를 배포하지 않는다.
- CLI는 JSON과 사람이 읽는 텍스트 출력을 지원한다.

## 완료 기준

- API와 CLI의 CRUD 및 상태 이동 시나리오가 자동 테스트를 통과한다.
- 실제 Supabase DB에는 기존 테이블을 유지하고 상태 열과 우선순위 라벨만 준비한다.
- README, 기술·DB·테스트 문서와 Codex 스킬을 제공한다.
